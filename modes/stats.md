# Mode: stats — 绩效统计与解读

脚本算数,你负责解读。**不要手算任何数字。**

```bash
make stats                                     # 全期
python3 scripts/stats.py --since 2026-08-01    # 指定起始
python3 scripts/stats.py --json                # 机器可读
```

数据源:`data/trades.tsv`(唯一真相源,规范见 `docs/DATA_CONTRACT.md`)。

---

## 脚本输出的口径(解读前必须清楚)

| 指标 | 口径 | 注意 |
|---|---|---|
| 实现盈亏 | **FIFO** 配对买卖 | 只统计已平掉的部分;未平仓的浮盈亏不在内 |
| 胜率 | 盈利的平仓配对 / 全部平仓配对 | 分数股会产生大量小额配对,**笔数少时胜率没有统计意义** |
| 平均持有天数 | 自然日,非交易日 | 跨周末会虚高 |
| 标签绩效 | 按卖出行的 `reason_tag` 归集(词表见 `config/reason-tags.toml`) | 买入标签只统计笔数与金额,不归集盈亏 |
| 检查点分布 | 按 `checkpoint` 列 | 用于看某个时点是不是系统性做得更差 |

## 解读框架

### 1. 先看笔数,再看比率

小账户 + 分数股 = 笔数少。**笔数 < 20 时,胜率和平均值都是噪音**,
这时候只看**绝对盈亏**和**单笔最大亏损**,不要解读百分比。

明确说出来:"当前 {n} 笔,样本不足以支撑胜率结论。"——比给一个假装精确的数字有用得多。

### 2. 规则审计段 —— 这一节最有价值

`make stats` 会读 `config/rules.toml`,逐条给出判定。**它检验的是你自己写的规则**,
本仓库不预设任何市场判断。

- **「数据不足」不是失败,是诚实。** 审计器在样本太少时拒绝下结论 ——
  拿两三笔盈利去验证一条你本来就相信的规则,是这套机制最容易退化的方式。
- **「不支持」比「支持」更有价值。** 它告诉你哪条纪律该修正或退役。
  一条从未被数据支持过的规则是包袱,不是资产。
- **买入标签不归集盈亏**(盈亏按卖出行的标签归集),所以涉及买入判断的规则
  通常只能用 `manual` 检验 —— 这是口径限制,不是规则不重要。

### 3. 标签绩效表怎么用

表里每个标签的笔数、金额、实现盈亏、胜率、均笔,是上面规则审计的原料。

- 某标签**笔数异常多** → 它承担了太多不同的决策,考虑拆细,
  否则无法区分其中哪一类真正有效。
- 某标签**从未出现** → 它在你的实际操作里不存在,考虑从
  `config/reason-tags.toml` 删掉,减少记账时的犹豫。
- 标签是**归集维度**:你怎么分类,决定了你能问出哪些问题。

### 4. 检查点分布看流程

- 操作是否**过度集中在某个检查点**?若与你在 `_strategy.md` 里的设计不符,说明流程没落地。
- 某检查点的实现盈亏**系统性为负** → 该时点的决策质量有问题,不是运气。
- 某检查点长期零操作 → 它还有存在必要吗?

### 5. 隐性成本(盈亏表里看不到的)

必须主动提出来,否则复盘会系统性偏向保守:

- **现金闲置的机会成本**:统计区间内 BP 超出你设定目标的天数占比,
  以及同期你的标的池涨了多少。这部分是**真实亏损**,只是不出现在实现盈亏里。
- **滑点**:正常时段的市价单没有价格保护。若 `trades.tsv` 的 `note` 里记了下单时报价,
  可以估算累计滑点 —— 笔数多、单笔小时,它会吃掉相当比例的收益。
- **反复评估未成交的候选**:连续多个检查点评估同一标的却始终没动手,期间价格变化多少。

## 输出格式

```markdown
## 绩效统计 · {区间}

### 一、总览
交易 {n} 笔({buy} 买 / {sell} 卖)· 实现盈亏 ${x}
{笔数不足时明确声明样本不足}

### 二、规则审计(来自 config/rules.toml)
| 规则 | 判定 | 数据 | 建议 |

### 三、标签绩效
| reason_tag | 笔数 | 实现盈亏 | 胜率 | 均笔 | 解读 |

### 四、检查点分布
| 检查点 | 笔数 | 实现盈亏 | 解读 |

### 五、隐性成本
BP 超目标天数 {x}/{y} 天 · 期间标的池涨幅 {z}% · 估算机会成本
{滑点估算 | 数据不足则声明}

### 六、给复盘的输入
{最值得在 review mode 里深挖的一条}
```

## 台账坏了怎么办

`stats.py` 会校验每一行的字段数、日期格式、`side` 值、`reason_tag` 是否在词表内、
数字列是否可解析。报错时:

1. 按脚本给出的行号修 `data/trades.tsv`。
2. **不要为了让脚本跑过就删行**——台账缺一笔,整段历史的 FIFO 配对都会错。
3. 券商记录是权威来源:用 `get_pnl_trade_history` / `get_equity_orders` 回补。
4. 若报『标签不在词表内』,是 `config/reason-tags.toml` 改过而旧行没同步 ——
   别删行,改标签(或保留旧标签直到它退出统计窗口)。
