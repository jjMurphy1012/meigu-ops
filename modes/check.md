# Mode: check — 盘中检查点决策(10:33 / 13:03 / 15:37 ET)

**目标:在这个检查点做出明确的买 / 卖 / 不动决策,并说清依据。**

三个检查点用**同一套决策流程**,只有默认倾向不同(见文末)。
`_mechanics.md` §1:**没有"这个时间点只能做哪类操作"的限制**,唯一门槛是判断合理、有依据。

---

## Step 0 — 时间与状态自检(不可跳过)

1. `date` + `TZ=America/New_York date`。迟到按 `_mechanics.md` §5 分级处置。
   **已过 16:00 → 禁止任何交易,只汇报。**
2. `get_equity_orders`(当日)核对真实成交——**不要基于记忆里的持仓做决策**。
3. **意图过期检查**:如果本次会话距上次分析已超 ~15 分钟或期间有中断/压缩/切模,
   前面的结论全部作废,必须重新拉行情。
4. 若刚经历 /compact 或切模型 → 先自检调度列表,缺失立即重建。

## Step 1 — 拉实时数据

- `get_equity_quotes`:全部持仓 + `SMH` `QQQ` `SPY` `TLT`(+ 本次要看的候选)
- `get_portfolio`:最新现金 / BP
- WebSearch:**只在需要解释异动或验证买入理由时用**。
  - 防守性卖出:可以只凭价格行为决策(搜索不可用也能做)。
  - **买入决策必须有新闻核查**;搜索不可用则默认不买。
  - 搜到利空**先核发布日期**,旧闻不能当当日跌因。

## Step 2 — 三问过滤(每个候选都要过)

### 问题一:它符合你的准入条件吗?

按 `modes/_strategy.md`「建仓 / 加仓」一节的判定标准逐条对照,**写出结论与依据**,
不要只说『感觉可以』。

> ⚠️ 这条判定的两端都是真实的失败:定得太严 → 长期不操作,机会成本以『没出现在
> 盈亏表里』的方式发生;定得太松 → 在情绪高点买入。若你连续多个检查点用同一条理由
> 挡住同一个候选,那不是纪律,是这条规则需要修正的信号 —— 记进复盘。

### 问题二:有没有硬约束挡住?

- 该标的是否在自身二元催化窗口内(`catalyst.blackout_hours`)?
  **注意边界**:窗口之外不要外推成『本周谨慎』;组合里其他标的不受影响。
- 同一标的**当日已操作过** → 不重复(`preflight` 会拦)。
- 该候选是否**已连续多个检查点评估却始终没动手**?那说明触发条件可能定得不现实 ——
  要么放宽、要么换标的、要么承认这条规则需要修正,不能原地循环。
- 加仓后单一标的会否超过 `position.max_single_pct`?
- 现金账户 T+1:今天卖的钱今天不能全部再买。

### 问题三:尺寸对不对?

**下单前必算:这笔金额 ÷ 该仓位当前市值 = ?%**

- 减仓:意图是『部分减』就必须确认卖出占比真的是小部分。仓位大跌、市值缩水到接近
  标准尺寸时,套用标准尺寸会变成近乎清仓 —— `preflight` 的「减仓占比」闸门会拦。
- 加仓:单笔用 `trade.size_std`,极强信号才到 `trade.size_max`;
  首仓不超过 `trade.first_entry_max_ratio`。
- 会不会造出**残值仓**(低于 `position.residual_threshold_ratio` 的零头)?

## Step 3 — 防守侧独立检查(每个检查点都要过一遍)

不管有没有买入候选,先问防守:

1. 盘前预案的**触发线**是否被击穿?
2. 你在 `_strategy.md` 里定义的**确认条件**是否成立?(注意幅度门槛 —— 温和波动不算确认)
3. 触发了 → 按你定义的处理顺序执行,不是平均减。
4. 你的规则怎么区分『可以承受的回撤』与『必须退出』?按那个区分走。
5. 执行时机的取舍也该被数据检验 —— 写进 `config/rules.toml` 让审计器盯着。

## Step 4 — 现金部署检查(进攻纪律)

```
BP / 总值 = ?%   vs   cash.bp_target_pct
```

- 超出你设定的目标 = 需要解释:给出缩小差距的具体动作,或**逐个点名**说明每个候选
  被什么理由挡住 —— 笼统说『没机会』是回避,不是结论。
- 连续多日不缩小差距,要在汇报里明确承认并记进复盘(闲置也是成本)。
- 若处于你定义的防守场景,可暂时偏离常态目标,但要写明**触发条件是什么、
  什么时候解除**——解除后必须切回,并给『切回来』也定一个条件。

## Step 5 — 决策与执行

- 结论是**买 / 卖** → 转 `modes/trade.md` 执行。
  同一检查点可以对**不同标的**执行多笔独立操作,但每一笔都要有独立、具体的依据。
- 结论是**不动** → 也要明确说出来,并逐个点名说明每个候选被什么理由挡住。
  **零操作必须是具体排查后的结论,不是回避。**

## 输出格式

```markdown
## {检查点时刻} 检查点 · {YYYY-MM-DD}(实际 ET {时间})

**状态**:当日已成交 {n} 笔 / BP {x}%(目标 <{y}%)/ 组合浮盈亏 {z}%

### 一、行情快照
{持仓逐行:现价 / 当日% / vs 成本% / 触发线距离}
{基准:SMH / QQQ / SPY / TLT 当日%}

### 二、防守检查
{触发线是否击穿 / 你的确认条件是否成立 / 结论}

### 三、候选评估
{每候选:三问过滤逐条结论 → 执行 or 挡住的具体理由}

### 四、现金部署
{BP% vs 目标 / 本点动作 or 全部被挡的逐个点名}

### 五、决策
{买/卖/不动 + 标的 + 金额 + 占该仓位市值% + reason_tag(取自 config/reason-tags.toml)+ 理由}

*以上为分析,不构成投资建议。*
```

## 三个检查点的默认倾向

| 检查点 | 默认倾向 | 说明 |
|---|---|---|
| **10:33** | 开盘波动消化后 | 开盘一小时的价格发现基本完成,是当日第一个信息相对完整的时点 |
| **13:03** | 午盘 | 上午趋势确认或反转;13:00 国债拍卖会影响利率类标的 |
| **15:37** | 盘中最后一个可靠窗口 | 盘后即便可用限价单,流动性更差、成交不确定,分数股还受合格性限制 |

**各时点的操作门槛差异由你在 `modes/_strategy.md`「时段偏好」一节定义** ——
本仓库不预设哪个时点该进攻、哪个时点该防守。

半日市(提前收盘)时,把 15:37 提前到**收盘前 23 分钟**。
